# Bundled hash database: provenance and licence

`database.json` in this folder is **not** ZZMM's own data. It is a mechanically
flattened copy of the per-character hash data from
[ZZZ-Mod-Fixer](https://github.com/Vonksdesu/ZZZ-Mod-Fixer), a community tool that
rewrites stale 3DMigoto hashes in Zenless Zone Zero skin mods. ZZZ-Mod-Fixer is a
continuation of the original fixer by **petrascyll**; the hash tables have been
maintained by petrascyll, Leotorrez, CaveRabbit, SilentNightSound, HammyCatte,
shaojiang and ConfoundedHermit, and are distributed in that project under the MIT
licence.

- Upstream repository: <https://github.com/Vonksdesu/ZZZ-Mod-Fixer>
- Commit the asset was generated from: `0aa483d6abbe40ba83d7a9d4b59f24a43b987c35`
  (2026-11-21, game version 3.0)
- Source path: `Source Codes/Assets/PlayerCharacterPYData/*.py` (100 character
  modules)
- Generated by: `generate_database.py` in this folder

Only *data* was copied. The engine in `src-tauri/src/fixer/` is an independent
Rust implementation written for ZZMM; no Python source is shipped or executed at
runtime.

## Regenerating

```bash
# From a checkout of ZZZ-Mod-Fixer (recommended: lets reviewers diff the source)
python src-tauri/assets/zzz-mod-fixer/generate_database.py --source <checkout> --out src-tauri/assets/zzz-mod-fixer/database.json

# Or fetch the pinned commit from GitHub
python src-tauri/assets/zzz-mod-fixer/generate_database.py --download --out src-tauri/assets/zzz-mod-fixer/database.json
```

The script fails on an unknown command class or an unknown parameter name, so a
new upstream command cannot slip into the asset without being ported (or
explicitly classified as buffer-pass work) first. `cargo test` separately asserts
that every command the asset declares is handled by the Rust engine.

Bump `REF` in the script deliberately when pulling in a newer upstream revision,
and mention the new commit here.
